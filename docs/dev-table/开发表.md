| 05 | 解锁与启动 | 自动解锁、四种启动方式、失败兜底与自动锁屏 | 实现执行链：<br>1) RunCoordinator 收到触发后先判断条件（仅充电 / 仅 WiFi / 仅屏幕熄灭），不满足就写日志并跳过；<br>2) 解锁交给 SystemUI 里的钩子：App 发送带签名权限 com.appscheduler.permission.DISMISS_KEYGUARD 的广播 com.appscheduler.action.DISMISS_KEYGUARD；钩子反射调用 KeyguardViewMediator 的候选方法收起锁屏，失败时退回「上滑 + 注入密码 + 校验」，密码为空时只走上滑；<br>3) 解锁失败且用户允许兜底：把任务写进 PendingStore，起 ACTION_WAIT 守候服务，监听 ACTION_USER_PRESENT，用户手动解锁后立即启动；超过最长等待（10–1800 秒，默认 120）就发超时通知并丢弃；<br>4) 启动按计划执行：forceColdStart=true 先 am force-stop 再启动；四种 launchMode —— COMPONENT=`am start -n`、WAIT=`am start -W -n`、MONKEY=`monkey -p <pkg> 1`、DESKTOP=`input keyevent 3` 后再 am start；解析启动 Activity 用 `cmd package resolve-activity --brief`，解析失败写日志并跳过；<br>5) 结果写 TaskItem.lastResult 与日志，全部成功 / 部分失败发通知；autoLock 打开时启动后若 N 秒（2–600，默认 5）无操作就熄屏上锁；<br>6) 每条 su 命令都要有超时（20 秒），不能在广播接收器里长时间阻塞。 | 真机上能锁屏状态下自动解锁并拉起目标 App；四种启动方式各跑一次成功；等待兜底在手动解锁后 3 秒内启动 | RunCoordinator.kt、RunService.kt、TaskRunner.java、XposedEntry.java、AutoLock.kt、schedule/UnlockReceiver.kt | HyperOS/MIUI 需要允许「自启动」与「后台弹出界面」；su 授权弹窗会吃掉第一次触摸，脚本里用 `su -c 'sleep 2; input tap …'` |
| 06 | 权限体检 | 七项体检 + LSPosed 实时握手 + 手动确认 | 实现 PermissionAudit，输出 7 行 PermRow（key/title/detail/status/actionLabel/action/secondAction/secondActionLabel）：<br>1) 通知权限：Android 13 起检查 POST_NOTIFICATIONS 运行时授权 + areNotificationsEnabled，缺任一即 MISSING，动作「申请」；<br>2) 精确闹钟：Android 12+ 检查 canScheduleExactAlarms，缺则 MISSING，动作跳系统「闹钟与提醒」；<br>3) 省电白名单：检查 isIgnoringBatteryOptimizations，缺则动作发 REQUEST_IGNORE_BATTERY_OPTIMIZATIONS；<br>4) root 权限：检测 su 二进制；有 su 未验证 → UNKNOWN + 「申请 root 权限」；验证过（audit prefs root_verified=true）→ VERIFIED；没有 su → MISSING；<br>5) 读取应用列表：查询已安装应用数量，太少（<20）提示被限制，动作「现在检查」触发一次查询；<br>6) LSPosed 模块：root 已验证时发 PING 广播（带随机 token），解析 logcat 里 `pong pid=… mediator=ready vc=… token=…`；没有回应 → UNKNOWN 并给出「启用模块 + 勾作用域系统界面 + 只重启系统界面」的文案；回应了但 vc 与 TaskRunner.HOOK_VERSION_CODE 不一致 → UNKNOWN + 「系统界面里载入的是钩子 vXX，这次安装的是 vYY，让它重启一次就会换新版，不用重启手机」；一致 → OK「实时检测通过」；root 未验证前只给「我已确认」手动入口；<br>7) 自启动 / 后台弹出界面：无法程序化检测，只能「我已确认」→ VERIFIED（写 audit prefs vendor_confirmed=true）。<br>所有手动确认写 apptimer_audit.xml，重新检测时保留。 | 真机上 7 行齐全；LSPosed 行显示 PID 与握手时间；改 HOOK_VERSION_CODE 后能出现「钩子版本待更新」分支 | permissions/PermissionAudit.kt、TaskRunner.java、apptimer_audit.xml（SharedPreferences） | 读 logcat 必须 `logcat -d -s AppTimer:I \| tail -n 8` 再匹配 token，不能 `logcat -d -t 20`（-t 按整块缓冲截断会漏行）；每次检测要 1 次 su + sleep 2，约 3 秒 |
